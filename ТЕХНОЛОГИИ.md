# Технологии проекта

Стек подобран под простое приложение без оверинжиниринга: классическая связка «SPA + REST API + одна БД», полностью на TypeScript и в Docker.

## Архитектура

```
┌────────────┐      HTTP /api      ┌────────────┐     Prisma     ┌──────────┐
│  Клиент    │  ───────────────▶   │  Сервер    │  ───────────▶  │  MySQL   │
│ React SPA  │   JSON + JWT        │  NestJS    │                │          │
│ :5173      │  ◀───────────────   │  :3000     │  ◀───────────  │  :3306   │
└────────────┘                     └────────────┘                └──────────┘
   antd, RTK Query                  Guards + DTO                   3 таблицы
```

Трёхуровневая клиент-серверная схема: представление (React), бизнес-логика (NestJS), данные (MySQL через Prisma). Каждый слой — отдельный контейнер.

## Почему именно так

### Клиент
- **React + TypeScript** — индустриальный стандарт для SPA; единый язык с сервером.
- **Redux Toolkit + RTK Query** — встроенный слой данных: запросы, кэш и автоинвалидация после мутаций «из коробки», без ручных thunk'ов.
- **Ant Design** — большой набор готовых компонентов (таблицы, формы, модалки) — быстро собирается админ-подобный интерфейс.
- **Vite** — мгновенный dev-сервер и быстрый билд.

### Сервер
- **NestJS** — структурированный каркас: модули по сущностям, внедрение зависимостей, декларативная авторизация через `Guards` и `@Roles`.
- **Prisma** — описание схемы в одном файле, автогенерация типобезопасного клиента и миграции одной командой.
- **JWT (passport-jwt)** — stateless-аутентификация, удобная для SPA.
- **bcryptjs** — чистый JS-вариант bcrypt (не требует нативной сборки в Alpine-образе).

### Инфраструктура
- **Docker Compose** — весь проект (БД + сервер + клиент) поднимается одной командой, ничего не нужно ставить на хост, кроме Docker.

## Ключевые технические решения

- **Prisma зафиксирована на 6.x, а не 7.x.** В Prisma 7 убрали `url = env(...)` в схеме (теперь нужен `prisma.config.ts` + driver-adapter). Для простого проекта это лишнее усложнение, поэтому используется стабильная 6-я версия с привычной конфигурацией.
- **bcryptjs вместо bcrypt** — чтобы избежать нативной компиляции в Alpine-контейнере.
- **`quantity` хранится как `DECIMAL`** и приходит на клиент строкой (особенность сериализации Decimal в JSON) — на клиенте учтено при выводе и редактировании.
- **Пароли никогда не возвращаются API** — выборки пользователей идут без поля `passwordHash`.
