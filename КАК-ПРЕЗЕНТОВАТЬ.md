# Как понять и презентовать проект «Пекарня»

Этот файл — пошаговый путеводитель для человека, который будет **открывать и показывать проект** (например, на защите), и которому не обязательно быть программистом. Идём сверху вниз: сначала поймём, *что это*, потом *как запустить*, потом *что показать и что говорить*.

> 💡 Если коротко: это веб-сайт для учёта в пекарне. Он запускается одной командой, открывается в браузере, в него входят по логину и паролю, и в нём можно вести списки ингредиентов, сотрудников и пользователей.

---

## Шаг 0. Что это за проект (своими словами)

Представь небольшую пекарню. Ей нужно вести учёт:
- **ингредиентов** (мука, сахар, дрожжи — сколько чего на складе и кто за это отвечает),
- **сотрудников** (кто работает и кем),
- **пользователей системы** (у кого есть доступ к программе и с какими правами).

Раньше это было настольное приложение (программа на одном компьютере). Мы сделали **современную веб-версию** — она открывается в браузере, к ней может подключаться несколько человек, данные хранятся централизованно.

Есть **две роли**:
- **Администратор** — видит и меняет всё (ингредиенты, сотрудников, пользователей).
- **Пользователь** — работает только с ингредиентами.

---

## Шаг 1. Что нужно на компьютере

Нужна всего одна программа — **Docker**.

> 🐳 **Что такое Docker простыми словами?** Это «коробка», которая сама внутри себя запускает всё необходимое для проекта — базу данных, сервер и сайт — одной командой. Не нужно ничего настраивать вручную: ни устанавливать базу данных, ни сервер. Docker делает это за тебя.

Проверить, что Docker установлен — открой терминал (командную строку) и введи:

```bash
docker --version
```

Если показалась версия (например, `Docker version 29.x`) — всё готово. Если «команда не найдена» — нужно установить Docker Desktop (с официального сайта docker.com).

---

## Шаг 2. Как запустить проект

1. Открой **терминал** в папке проекта (там, где лежит файл `docker-compose.yml`).
2. Введи команду и нажми Enter:
   ```bash
   docker compose up -d --build
   ```
3. **Подожди.** В первый раз это занимает пару минут (скачиваются и собираются компоненты). Дальше — несколько секунд.
4. Открой браузер и зайди на адрес:
   ```
   http://localhost:5173
   ```
5. Появится экран входа. Введи:
   - **Логин:** `admin`
   - **Пароль:** `admin`

Готово — ты внутри. 🎉

> Если что-то пошло не так — загляни в [ЗАПУСК.md](ЗАПУСК.md), там разобраны частые проблемы (занятый порт, перезапуск и т.д.).

Когда закончишь — остановить проект можно командой:
```bash
docker compose down
```

## Шаг 3. Что показать (сценарий демонстрации)

Это готовый сценарий «живой» демонстрации. Лучше показывать на чистой базе — тогда добавление данных будет наглядным.

1. **Экран входа.** Войди администратором.
   *Можно сказать:* «Вход защищён логином и паролем. Пароли хранятся не как есть, а в зашифрованном виде».

2. **Раздел «Ингредиенты».** Покажи таблицу. Нажми **«Добавить»**, заведи ингредиент: например *Мука, кг, 50*, выбери ответственного сотрудника.
   *Можно сказать:* «Здесь полноценный учёт: добавление, редактирование, удаление, поиск».

3. **Раздел «Сотрудники».** Добавь сотрудника (*Иван Иванов, Пекарь*).
   *Можно сказать:* «Сотрудники и ингредиенты связаны: у каждого ингредиента есть ответственный».

4. **Раздел «Пользователи».** Создай нового пользователя с ролью **«Пользователь»** (например, логин `baker`).
   *Можно сказать:* «Учётные записи и права заводит администратор».

5. **Покажи роли в действии.** Выйди (кнопка «Выход») и войди под новым пользователем `baker`.
   *Обрати внимание комиссии:* теперь в меню остался **только раздел «Ингредиенты»** — разделы «Сотрудники» и «Пользователи» скрыты.
   *Можно сказать:* «Это разграничение доступа: обычный пользователь не видит административные разделы».

6. **Поиск.** Вернись под админом, в ингредиентах воспользуйся строкой поиска по названию.

Этого сценария достаточно, чтобы показать **все ключевые возможности**: вход, роли, работу с данными, связи и поиск.

## Шаг 4. Как объяснить, как это устроено (простыми словами)

Если спросят, из чего состоит проект — объясни, что он из **трёх частей**:

| Часть | Простыми словами | Технология |
|---|---|---|
| **Сайт** (то, что видно в браузере) | «Лицо» программы — кнопки, таблицы, формы | React + Ant Design |
| **Сервер** (невидимый «мозг») | Принимает запросы, проверяет права, считает логику | NestJS |
| **База данных** (хранилище) | Где лежат все данные — как умные таблицы Excel | MySQL |
| **Docker** | «Коробка», которая запускает все три части вместе | Docker |

> Не нужно углубляться в детали — достаточно знать названия и одну фразу про каждую часть. Подробности, если попросят, есть в [ТЕХНОЛОГИИ.md](ТЕХНОЛОГИИ.md).

## Шаг 5. Частые вопросы на защите (и ответы)

**— Где и как хранятся данные?**
В базе данных MySQL, в трёх таблицах: пользователи, сотрудники, ингредиенты. Подробная схема — в [БАЗА-ДАННЫХ.md](БАЗА-ДАННЫХ.md).

**— Насколько это безопасно?**
Пароли не хранятся в открытом виде — только их зашифрованный «отпечаток» (хеш). После входа выдаётся защищённый токен, а доступ к разделам ограничен ролями.

**— Что именно умеет программа?**
Добавлять, изменять, удалять и искать записи по трём разделам; разграничивать права администратора и пользователя.

**— Почему выбраны такие технологии?**
Это современный и распространённый набор; и сайт, и сервер написаны на одном языке (TypeScript), что упрощает разработку. Весь проект запускается одной командой через Docker.

**— Чем веб-версия лучше прежней настольной?**
Доступна из браузера, не требует установки на каждый компьютер, поддерживает несколько пользователей одновременно, данные хранятся централизованно.

**— Можно ли это развивать дальше?**
Да. Логично добавить учёт продаж, заказы, поставщиков, отчёты — структура это позволяет.
