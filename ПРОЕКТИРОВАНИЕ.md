# Проектирование веб-версии ИС «Пекарня»

Технический дизайн веб-приложения. Опирается на [ОПИСАНИЕ-ПРОЕКТА.md](ОПИСАНИЕ-ПРОЕКТА.md) (тема, предметная область, исходная модель данных). Принцип — просто и практично, без оверинжиниринга.

## 1. Стек

| Слой | Технологии |
|---|---|
| **Клиент (SPA)** | React + Vite, TypeScript, Redux Toolkit + RTK Query, Ant Design, React Router |
| **Сервер (REST API)** | Node.js + NestJS, TypeScript, Prisma, JWT (Guards + `@Roles`), class-validator |
| **БД** | MySQL / MariaDB |
| **Инфраструктура** | Docker + Docker Compose (контейнеры: `db`, `server`, `client`) |

Состав — **3 сущности**: ингредиенты, сотрудники, пользователи (как в десктоп-версии; проекты/задачи не добавляем).

## 2. Структура репозитория

Монорепо из двух независимых папок (без workspace-инструментов — так проще):

```
project/
├─ ПРОЕКТИРОВАНИЕ.md
├─ docker-compose.yml          # сервисы: db (MySQL) + server + client
├─ .env                        # пароли БД, JWT_SECRET (не в git)
├─ .env.example                # шаблон переменных окружения
├─ server/                     # NestJS API
│  ├─ Dockerfile
│  ├─ .dockerignore
│  ├─ prisma/
│  │  ├─ schema.prisma
│  │  └─ seed.ts               # создаёт админа по умолчанию
│  ├─ src/
│  │  ├─ main.ts               # bootstrap: ValidationPipe, CORS, префикс /api
│  │  ├─ app.module.ts
│  │  ├─ prisma/               # PrismaModule + PrismaService
│  │  ├─ auth/                 # login, JWT strategy, JwtAuthGuard, RolesGuard, @Roles
│  │  ├─ users/                # CRUD (только admin)
│  │  ├─ employees/            # CRUD
│  │  └─ ingredients/          # CRUD
│  └─ package.json
└─ client/                     # React + Vite
   ├─ Dockerfile
   ├─ .dockerignore
   ├─ src/
   │  ├─ main.tsx, App.tsx
   │  ├─ app/store.ts          # configureStore
   │  ├─ app/api.ts            # RTK Query baseApi (Bearer-токен в заголовке)
   │  ├─ features/auth/        # authSlice (token+user), LoginPage
   │  ├─ features/ingredients/ # api + страница (Table) + модалка (Form)
   │  ├─ features/employees/
   │  ├─ features/users/
   │  ├─ components/           # AppLayout (antd Layout+Menu), ProtectedRoute
   │  └─ routes.tsx
   ├─ vite.config.ts           # proxy /api → server:3000
   └─ package.json
```

`DATABASE_URL` и `JWT_SECRET` сервер получает из окружения, заданного в `docker-compose.yml` (значения — из корневого `.env`), поэтому отдельный `server/.env` для контейнера не нужен.

## 3. Модель данных (Prisma)

Имена переводим на латиницу (раздел 8 описания). Маппинг со старой БД:

| Старая таблица/поле | Новая модель/поле | Изменение |
|---|---|---|
| `Пользователь.IDПользователя` | `User.id` | autoincrement |
| `Пользователь.Логин` | `User.login` | `@unique` |
| `Пользователь.Пароль` | `User.passwordHash` | **bcrypt-хеш** вместо открытого текста |
| `Пользователь.Роль` | `User.role` | **enum** `admin`/`user` вместо строки |
| `Сотрудники.IDСотрудника` | `Employee.id` | autoincrement |
| `Сотрудники.ФИО` | `Employee.fullName` | — |
| `Сотрудники.Должность` | `Employee.position` | — |
| `Ингредиенты.IDИнгредиента` | `Ingredient.id` | autoincrement |
| `Ингредиенты.Имя` | `Ingredient.name` | — |
| `Ингредиенты.ЕдиницаИзмерения` | `Ingredient.unit` | — |
| `Ингредиенты.Количество` | `Ingredient.quantity` | **число** (Decimal) вместо строки |
| `Ингредиенты.IDСотрудника` | `Ingredient.employeeId` | FK, nullable |

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}

enum Role {
  admin
  user
}

model User {
  id           Int    @id @default(autoincrement())
  login        String @unique
  passwordHash String
  role         Role   @default(user)
}

model Employee {
  id          Int          @id @default(autoincrement())
  fullName    String
  position    String?
  ingredients Ingredient[]
}

model Ingredient {
  id         Int       @id @default(autoincrement())
  name       String
  unit       String?
  quantity   Decimal   @default(0) @db.Decimal(10, 2)
  employee   Employee? @relation(fields: [employeeId], references: [id], onDelete: SetNull)
  employeeId Int?
}
```

Связь: **Employee 1 → N Ingredient** (ответственный за ингредиент). Удаление сотрудника обнуляет `employeeId` у ингредиентов (`onDelete: SetNull`) — соответствует исходной необязательной связи.

## 4. REST API

Глобальный префикс `/api`. Формат — JSON. Аутентификация — заголовок `Authorization: Bearer <token>`.

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `POST /api/auth/login` | публично | `{login, password}` → `{accessToken, user}` |
| `GET /api/auth/me` | user, admin | текущий пользователь по токену |
| `GET /api/ingredients?search=` | user, admin | список (+ поиск по названию) |
| `POST /api/ingredients` | user, admin | создать `{name, unit, quantity, employeeId?}` |
| `PATCH /api/ingredients/:id` | user, admin | изменить |
| `DELETE /api/ingredients/:id` | user, admin | удалить |
| `GET /api/employees` | user, admin | список (нужен для выбора ответственного) |
| `POST /api/employees` | **admin** | создать `{fullName, position?}` |
| `PATCH /api/employees/:id` | **admin** | изменить |
| `DELETE /api/employees/:id` | **admin** | удалить |
| `GET /api/users` | **admin** | список |
| `POST /api/users` | **admin** | создать `{login, password, role}` |
| `PATCH /api/users/:id` | **admin** | изменить (пароль — заново хешируется) |
| `DELETE /api/users/:id` | **admin** | удалить |

### Матрица ролей

| Ресурс | `user` | `admin` |
|---|---|---|
| Ингредиенты (CRUD) | ✅ | ✅ |
| Сотрудники — чтение | ✅ | ✅ |
| Сотрудники — изменение | ❌ | ✅ |
| Пользователи (всё) | ❌ | ✅ |

Логика повторяет десктоп: обычный пользователь работает с ингредиентами (и видит сотрудников для выбора ответственного), администратор управляет всем. **Публичной регистрации нет** — учётные записи создаёт админ (как в исходном приложении).

## 5. Авторизация

- При входе сервер ищет пользователя по `login`, сверяет пароль через `bcrypt.compare`, выдаёт **JWT** (`{ sub: id, login, role }`, срок ~1 день), подписанный `JWT_SECRET`.
- Защита маршрутов: `JwtAuthGuard` (passport-jwt) проверяет токен; `RolesGuard` + декоратор `@Roles('admin')` проверяет роль из токена.
- Клиент хранит токен и данные пользователя в `localStorage` (через `authSlice`), RTK Query добавляет `Bearer` в каждый запрос. По 401 — разлогин и редирект на `/login`.
- Сид (`prisma/seed.ts`) создаёт администратора по умолчанию (логин `admin`, пароль из env, например `admin`), чтобы было чем войти при первом запуске.

## 6. Сервер (NestJS)

Модульная структура, каждый ресурс генерируется через `nest g resource`:

- **PrismaModule** — `PrismaService` (обёртка над `PrismaClient`), общий провайдер.
- **AuthModule** — `AuthController` (`login`, `me`), `AuthService`, `JwtStrategy`, гварды, `LoginDto`.
- **UsersModule / EmployeesModule / IngredientsModule** — `*Controller` + `*Service` (CRUD через Prisma) + DTO (`Create*Dto`, `Update*Dto`) с `class-validator`.
- В `main.ts`: глобальный `ValidationPipe({ whitelist: true })`, `app.enableCors()`, `app.setGlobalPrefix('api')`.

## 7. Клиент (React)

- **store** (`configureStore`): редьюсеры RTK Query `baseApi` + `authSlice`.
- **baseApi** (RTK Query): `baseUrl: '/api'`, `prepareHeaders` подставляет токен; эндпоинты-инжекты по фичам (`ingredientsApi`, `employeesApi`, `usersApi`, `authApi`) с тегами для авто-инвалидации кэша после мутаций.
- **Роутинг** (React Router): `/login` — публично; всё остальное под `ProtectedRoute` внутри `AppLayout`:
  - `/` → редирект на `/ingredients`
  - `/ingredients`, `/employees`, `/users` (последние два — только для admin; пункты меню скрыты для user, маршруты закрыты гвардом по роли).
- **AppLayout** — antd `Layout` + `Menu` (аналог вкладок дашборда), в шапке — имя пользователя и кнопка «Выход».
- **Страница сущности** — antd `Table` со списком + кнопки «Добавить»/«Редактировать»/«Удалить»; добавление/редактирование — antd `Modal` + `Form` (аналог диалогов десктопа), удаление — через `Popconfirm`. На форме ингредиента — `Select` ответственного сотрудника (данные из `GET /employees`).

## 8. План сборки (по шагам)

**Сервер:**
1. Инициализировать `server/` (NestJS), поставить `prisma`, `@prisma/client`, `@nestjs/jwt`, `@nestjs/passport`, `passport-jwt`, `bcrypt`, `class-validator`, `class-transformer`.
2. `.env` (`DATABASE_URL`, `JWT_SECRET`), `schema.prisma`, `prisma migrate dev`, `prisma generate`. Сид админа.
3. PrismaModule/Service → AuthModule (login + JWT + guards) → Users/Employees/Ingredients (CRUD + DTO + роли).
4. `main.ts`: ValidationPipe, CORS, префикс `/api`.

**Клиент:**
5. Инициализировать `client/` (`npm create vite@latest -- --template react-ts`), поставить `antd`, `@reduxjs/toolkit`, `react-redux`, `react-router-dom`.
6. `vite.config.ts` — proxy `/api` → `localhost:3000`. store + baseApi + authSlice.
7. AppLayout, роутинг, ProtectedRoute, LoginPage.
8. Страницы 3 сущностей (Table + Modal Form + Popconfirm).

**Docker и интеграция:**
9. `docker-compose.yml` (db + server + client) + `Dockerfile` для server и client + `.env` → запуск `docker compose up`.
10. Прогон end-to-end (раздел 9).

## 9. Запуск и проверка (через Docker)

Весь проект поднимается одной командой — из инструментов нужен только установленный Docker.

- **Поднять стек:** `docker compose up --build` — стартуют три контейнера:
  - `db` — MySQL (порт `3306`), данные в именованном volume;
  - `server` — NestJS (порт `3000`), `DATABASE_URL` указывает на хост `db`;
  - `client` — Vite dev-сервер (порт `5173`), запросы `/api` проксируются на `server:3000`.
- **Миграции и сид:** при первом запуске — внутри контейнера сервера: `docker compose exec server npx prisma migrate deploy` и сид админа (или повесить на entrypoint).
- **Открыть:** http://localhost:5173 — вход админом (`admin` / пароль из `.env`).
- **Сценарий приёмки:**
  1. Вход админом.
  2. Создать сотрудника → он появляется в списке.
  3. Создать ингредиент, выбрав ответственного сотрудника → отредактировать → удалить.
  4. Создать пользователя с ролью `user`, войти под ним → видны только ингредиенты, разделы «Сотрудники»/«Пользователи» недоступны.
  5. Проверить, что запрос к `/api/users` под ролью `user` возвращает 403.

## 10. Открытые мелочи (можно решить по ходу)

- Пароль админа по умолчанию вынести в `.env` (не хардкодить).
- `quantity` сделан `Decimal` (допускает дробные кг/л); если нужны только целые — заменить на `Int`.
- Поиск/фильтрация пока только по ингредиентам; при желании добавить и на других страницах.
