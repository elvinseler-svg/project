# Инструкция по запуску

## Требования

- **Docker** и **Docker Compose** (Docker Desktop или Docker Engine).
  Больше ничего ставить не нужно — Node.js, MySQL и зависимости работают внутри контейнеров.

Проверить, что Docker установлен:

```bash
docker --version
docker compose version
```

## Запуск

Из корня проекта:

```bash
docker compose up -d --build
```

Команда соберёт образы и поднимет три контейнера:

| Контейнер | Сервис | Порт | Назначение |
|---|---|---|---|
| `project-db-1` | MySQL 8.4 | `3306` | База данных |
| `project-server-1` | NestJS API | `3000` | REST API (`/api`) |
| `project-client-1` | Vite (React) | `5173` | Веб-интерфейс |

При первом старте контейнер `server` автоматически: сгенерирует Prisma Client, применит миграции и засеет администратора.

## Вход

Открыть в браузере **http://localhost:5173** и войти:

- **Логин:** `admin`
- **Пароль:** `admin`

> Учётная запись администратора создаётся сид-скриптом. Логин и пароль можно изменить в файле `.env` (`ADMIN_LOGIN`, `ADMIN_PASSWORD`) до первого запуска.

## Переменные окружения

Настройки — в файле [.env](.env) в корне (шаблон — [.env.example](.env.example)):

```ini
MYSQL_ROOT_PASSWORD=rootpass        # пароль root в MySQL
MYSQL_DATABASE=bakery               # имя базы данных
DATABASE_URL=mysql://root:rootpass@db:3306/bakery   # строка подключения (хост db — имя контейнера)
JWT_SECRET=dev-secret-change-me     # секрет для подписи JWT
PORT=3000                           # порт сервера
ADMIN_LOGIN=admin                   # логин администратора по умолчанию
ADMIN_PASSWORD=admin                # пароль администратора по умолчанию
```

> Для реального использования обязательно смените `JWT_SECRET` и пароли.

## Полезные команды

```bash
docker compose up -d --build      # собрать и запустить (или применить изменения)
docker compose ps                 # статус контейнеров
docker compose logs -f server     # логи сервера (потоково)
docker compose logs -f client     # логи клиента
docker compose restart server     # перезапустить сервер
docker compose down               # остановить (данные БД сохранятся в volume)
docker compose down -v            # остановить и удалить данные БД (полный сброс)
```

Разработка идёт с горячей перезагрузкой: правки в `server/` и `client/` подхватываются автоматически (исходники примонтированы в контейнеры).

## Работа с базой данных вручную

Если нужно выполнить миграции/сид вручную внутри контейнера:

```bash
docker compose exec server npx prisma migrate deploy   # применить миграции
docker compose exec server npx prisma db seed           # засеять админа
docker compose exec server npx prisma studio            # открыть просмотрщик БД
```

Подключиться к MySQL напрямую:

```bash
docker compose exec db mysql -uroot -prootpass bakery
```

## Устранение неполадок

| Проблема | Решение |
|---|---|
| Порт `5173`/`3000`/`3306` занят | Освободить порт или изменить маппинг в [docker-compose.yml](docker-compose.yml) (`"5173:5173"` → `"5174:5173"`). |
| Сервер не стартует | Посмотреть `docker compose logs server` — обычно ждёт готовности БД (есть healthcheck, должен подняться сам). |
| Изменили зависимости (`package.json`) | Пересобрать образы: `docker compose up -d --build`. |
| Нужно начать с чистой БД | `docker compose down -v && docker compose up -d --build`. |
| Warning «`package.json#prisma` is deprecated» | Безвреден — относится к будущей Prisma 7, проект на Prisma 6 (см. [ТЕХНОЛОГИИ.md](ТЕХНОЛОГИИ.md)). |

## Запуск без Docker (необязательно)

Если хочется запускать локально, понадобятся **Node.js 20+** и доступный **MySQL**. Проще всего поднять только БД в Docker:

```bash
# 1. База данных
docker compose up -d db

# 2. Сервер (в каталоге server/)
cd server
npm install
DATABASE_URL="mysql://root:rootpass@localhost:3306/bakery" npx prisma migrate deploy
DATABASE_URL="mysql://root:rootpass@localhost:3306/bakery" npx prisma db seed
DATABASE_URL="mysql://root:rootpass@localhost:3306/bakery" npm run start:dev

# 3. Клиент (в каталоге client/, в отдельном терминале)
cd client
npm install
npm run dev
```

Затем открыть http://localhost:5173 (клиент проксирует `/api` на `http://localhost:3000`).
